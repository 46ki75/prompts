## Answer

A recursive CTE uses `WITH RECURSIVE` and consists of two parts joined
by `UNION ALL` (or `UNION`):

1. **Anchor member** — a non-recursive seed query.
2. **Recursive member** — a query that references the CTE name itself,
   producing the next iteration from the previous one.

PostgreSQL evaluates it by:

- running the anchor to produce an initial working set,
- repeatedly running the recursive member against the current working
  set to produce a new working set,
- accumulating all rows into the final CTE result,
- stopping when an iteration produces no new rows.

### Minimal example: count 1 through 10

```sql
WITH RECURSIVE counter(n) AS (
    SELECT 1                              -- anchor
    UNION ALL
    SELECT n + 1 FROM counter WHERE n < 10 -- recursive step
)
SELECT n FROM counter;
```

### Practical example: walk a tree (employees -> manager)

Given `employees(id, name, manager_id)`:

```sql
WITH RECURSIVE org_chart AS (
    SELECT id, name, manager_id, 1 AS depth
    FROM employees
    WHERE manager_id IS NULL              -- roots

    UNION ALL

    SELECT e.id, e.name, e.manager_id, oc.depth + 1
    FROM employees e
    JOIN org_chart oc ON e.manager_id = oc.id
)
SELECT * FROM org_chart ORDER BY depth, id;
```

### Practical example: graph traversal with cycle protection

For graphs that may contain cycles, accumulate the path and exclude
already-visited nodes. PostgreSQL 14+ also supports a built-in
`CYCLE` clause, and `SEARCH` for ordering — these are the more recent
additions, so if you need exact current behavior I would normally
verify against the official docs (which I cannot fetch here):

```sql
WITH RECURSIVE reachable AS (
    SELECT src, dst, ARRAY[src, dst] AS path, false AS cycle
    FROM edges
    WHERE src = 1

    UNION ALL

    SELECT r.src, e.dst, r.path || e.dst, e.dst = ANY(r.path)
    FROM reachable r
    JOIN edges e ON e.src = r.dst
    WHERE NOT r.cycle
)
SELECT * FROM reachable;
```

## Key rules and gotchas

- The keyword is `WITH RECURSIVE`, even if only one CTE in the
  statement is actually recursive.
- The recursive member must reference the CTE name **exactly once**
  and cannot use it inside an aggregate, `LEFT JOIN` on the recursive
  side, subquery `NOT IN`, or other constructs that would break the
  fixed-point evaluation. The docs enumerate the exact restrictions.
- Use `UNION ALL` unless you specifically need duplicate elimination;
  `UNION` forces a distinctness check each iteration and is slower.
- Always include a terminating condition (e.g., `WHERE n < 10`,
  `WHERE NOT cycle`). Without one, the query runs until it errors or
  exhausts resources.
- For unbounded exploration, guard with either the `CYCLE` clause
  (PostgreSQL 14+) or a manual visited-set as shown above.
